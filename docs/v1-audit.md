# Horizon Compact v1: the definition-of-done audit

> **2026-11-24 (Claude, Opus; Phase 7 step 6), re-verified at step 7 the same day:** 28 rows sent to cold agents with
> no working history, in three batches, then the six corrected or disputed rows to a fresh one; every row now agrees
> (`docs/phases/evidence/phase-7/audit-sample/`). Step 8 reads the README against it. A row changes only with a dated
> note saying what changed and why. **Waived** is his alone, and always dated.

This audit checks v1 against what it promised: the design brief's definition of done (`docs/planning/00` §8), every
phase's own definition of done, the eval spec (`docs/planning/07`), the one-way doors (`docs/planning/05` §3.1,
`CLAUDE.md`), and lists everything still open. Each row gives the promise and where it was made, a status, the
evidence a reader can follow (a commit, a file, a run id or a URL), and **README** where the README relies on it.

**The statuses.** **Met:** done as promised, or as changed by a dated decision made before it could be judged on
results, with the change named. **Partial:** some of it done; the row says which part is not. **Not met.** **Waived:**
his decision, dated. Where a row has parts, it takes the status of its weakest part. The phase audits in Part B are
cited, not redone: each phase row carries its weakest row's status, and one item per phase was checked again here.

**How the evidence was read.** Every file, line and run id below was opened on 2026-11-24. The GitHub run ids were read
with `gh run view` that day (each `success`, on the commit named); the live site's paths were fetched that day;
`uv run hc site raw-verify` was run that day. A grep that found nothing is reported as a search, not as proof.
